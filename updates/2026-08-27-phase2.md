# SultraKita Phase 2 — UI/UX QA Notes

Spesifikasi Phase 2 dipetakan additive ke homepage existing. Markup mempertahankan ID penting seperti `search`, `location-pill`, `listings`, `district`, `sort`, `open-sell`, dan `mobile-sell` agar seluruh handler existing tetap kompatibel.

Perubahan markup meliputi alias `topbar-v2`, tiga area topbar (`topbar-left`, `topbar-center`, `topbar-right`), sidebar navigation dua grup dengan shortcut Beranda/Jelajah/Kategori/Lowongan/Properti/Kendaraan/Jasa/Donasi serta Favorit/Iklan Saya/Pesan, hero compact, category strip, filter bar, listing grid V2, dan alias listing card/card media/card body/card actions pada renderer JS. Shortcut kategori properti/kendaraan/jasa memakai `data-category-nav` dan mengalihkan ke state filter existing. Shortcut donasi memicu tombol kampanye donasi existing.

QA awal mendeteksi browser masih memakai CSS/JS cache lama karena URL cache-buster sebelumnya tidak berubah setelah modifikasi. Cache-buster kemudian dinaikkan menjadi `tropical-commerce-2-dense` untuk CSS dan `dense-layout-4` untuk JS sebelum QA ulang. Temuan ini bersifat cache invalidation, bukan error layout.


QA setelah cache-buster baru: topbar memiliki tiga sibling area (`topbar-left`, `topbar-center`, `topbar-right`), sidebar memiliki dua grup nav, category strip terhitung `display:flex` dengan `overflow-x:auto`, dan listing grid menggunakan empat kolom pada viewport desktop. Shortcut kategori kemudian diselaraskan ke event handler discovery existing melalui `data-category`, sehingga state filter, URL, render kategori, dan loading listing tetap satu sumber kebenaran.


QA terbaru di browser: category strip ter-render horizontal dan listing grid tetap dense. DOM topbar terverifikasi memiliki tiga sibling area, sidebar dua grup nav, dan shortcut Properti berhasil mengubah URL menjadi `?category=properti`, memilih kategori Properti, serta mempertahankan event discovery existing. Cache-buster JS kini memakai `dense-layout-5`.


Listing renderer kini mempertahankan data dan event existing, tetapi menambahkan alias card Phase 2 serta elemen informasi opsional: badge seller terverifikasi, jumlah foto jika API menyediakannya, price row, judul dua baris, metadata lokasi/kategori, tag kategori, seller info, dan quick actions. Lint serta build marker kembali lulus setelah perubahan.


QA visual final lokal: viewport CSS 1280×1100 memakai topbar grid tiga kolom (`307.672px 519.188px 346.125px`), category strip `display:flex`, `overflow-x:auto`, gap 10px, dan shortcut donasi tersedia. Tidak ada listing lokal pada database test environment sehingga card renderer tidak tampil; empty state tetap ter-render. Script aktif memakai `/app.js?v=phase2-dense-1`.


Smoke test lokal setelah restart menunjukkan health service aktif tetapi `/api/stats` tidak dapat mengakses database karena environment sandbox tidak menyediakan `DATABASE_URL`; log menyatakan `DATABASE_URL wajib dikonfigurasi; SQLite/penyimpanan ephemeral tidak didukung.` Ini adalah keterbatasan environment lokal, bukan perubahan Phase 2. Verifikasi backend production akan mengandalkan CI container dan endpoint live.
